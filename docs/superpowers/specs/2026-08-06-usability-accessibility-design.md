# 수업용 집중 타이머 — 사용성·접근성 개선 설계

> 상태: **설계 확정, 구현 전** (2026-08-06) · 대상 파일 `index.html`

## Context

`index.html`은 이미 상당한 접근성 기반을 갖춘 단일 파일 수업 타이머다 (`aria-label`,
`aria-live`, `focus-visible`, `prefers-reduced-motion`, 색상 명암비 경고 등 — `PLAN.md` 참고).
이번 작업은 **기존 화면을 더 편리하고 접근성 좋게 다듬는 것**이 중심이고, 그 과정에서
필요하다고 판단된 작은 기능 몇 개(B)가 함께 포함됐다. 대화 중 아래 순서로 스코프가 확정됐다.

1. 사용성/접근성 전반 점검 요청 → 코드 점검으로 5개 접근성 공백 발견
2. "10초 카운트다운 효과음", "+10초/+1분 시간 추가 버튼" 추가 요청
3. "보조 컨트롤 버튼이 단순하지 않다", "설정을 접이식 사이드바로" 추가 요청
4. "설정 요소들의 명칭·구분이 직관적이지 않다" → 설정 패널 정보 구조 정리 요청
5. "글자색 기본값을 내가 정하고 싶다" → 텍스트 색상 커스터마이즈 요청

총 15개 항목. 모두 같은 파일(`index.html`) 안에서 이뤄지는 점진적 수정이라 별도 프로젝트로
쪼개지 않고 하나의 설계 문서로 관리한다. 구현 계획(다음 단계)에서 여러 단계/PR로 나누는 건
자연스럽다 — 이 문서는 "무엇을, 왜"까지만 다룬다.

## A. 접근성 — 기존 화면의 공백 메우기

### A1. 상태 전환 음성 안내 강화
현재 `$("live")` (`aria-live="polite"`)는 1분마다 "남은 시간 약 N분"만 채운다
(`index.html:1267`). 아래 전환 시점에 별도로 안내 문구를 채운다:
- 시작 / 일시정지
- 다음 단계 시작 (자동 진행 포함) — "{단계명} 시작, {분}분"
- 자동 진행 꺼짐 상태에서 다음 단계 대기 — "다음 단계 준비됨, 시작을 누르세요"
- 전체 종료 — "모든 단계가 끝났습니다"

분당 안내와 겹치지 않게, 상태 전환 안내는 그 시점에 한 번만 채우고 분당 안내를
덮어써도 무방하다(같은 `aria-live` 영역이므로 최신 값만 읽힌다).

### A2. 제목 편집 어포던스 (`#stepName`)
`canEdit`이 true일 때 `aria-label="제목: {현재 이름}. 눌러서 고쳐 쓸 수 있습니다"`를
동적으로 설정하고, false일 때는 `aria-label`을 제거해 일반 텍스트로 읽히게 한다
(`index.html:1336` 부근, `canEdit`/`lastEditable` 계산 지점). 기존 `title` 툴팁(마우스 전용)은 유지한다.

### A3. 설정 패널 포커스 관리
`togglePanel()`(`index.html:1791`)이 여닫을 때:
- 열 때: 패널 안 첫 포커스 가능 요소로 포커스 이동
- 닫을 때(토글·`Esc`·바깥 클릭 무관): 패널을 연 트리거 요소(C2 적용 이후에는 사이드바 탭)로 포커스 복귀
- 폭 680px 미만(패널이 전체 화면을 덮는 구간, 기존 미디어쿼리 기준)에서는
  `matchMedia`로 감지해 패널이 열려 있는 동안 `Tab`이 패널 밖(스테이지)으로 못 나가게
  가벼운 포커스 트랩을 추가한다. 680px 이상(패널·스테이지 나란히 배치)에서는 트랩을 걸지 않는다.

### A4. 1분 전 경고에 색상 외 신호 추가
10초 전(`data-warn="danger"`)은 펄스 애니메이션이 있어 색맹이어도 알아채지만
1분 전(`data-warn="warn"`)은 색상 변화뿐이다. `body[data-warn="warn"]`일 때 카운터
근처에 CSS `::before`/`::after`로 그린 정적 인디케이터(이모지/아이콘 폰트 없이 도형으로)를
추가한다. 애니메이션이 아니므로 `prefers-reduced-motion`과 무관하게 항상 표시된다.

### A5. 미니 버튼 터치 타겟 확대
`.step .mini button`(`index.html:312`, ↑↓✕ 버튼)의 기본 패딩 `6px 7px`(실질 ~25×27px)를
최소 24px 이상 확보되도록 키운다. 이미 모바일 브레이크포인트(`:413`)엔 `8px 9px` 규칙이
있으므로, 그 사이 구간(태블릿 등 데스크톱 미디어쿼리 미적용 폭)도 커버되게 기본값 자체를 올린다.

## B. 새 기능

### B1. 시간 추가 버튼 (+10초 / +1분)
`running` 또는 `paused` 상태일 때만 활성화되는 버튼 두 개 (`idle`/`finished`에서는 비활성 —
기존 `nextBtn` 비활성화 패턴과 동일). 눌리면:
- `remainingMs`와 `totalMs`를 같이 늘려 게이지 비율이 깨지지 않게 한다
- `running` 중이면 `endsAt`도 같이 밀어 마감시각 기반 엔진과 어긋나지 않게 한다
- `absoluteEnd`(이 시각까지 모드)가 있으면 목표 시각 자체를 밀어 의미를 유지한다
- 늘어난 시간이 1분/10초 경고 임계값을 다시 벗어나면 `preWarned`와 B2의 초당 카운트다운
  진행 플래그를 리셋해, 나중에 그 구간에 다시 들어왔을 때 정상적으로 다시 울리게 한다
- A1의 안내 문구를 재사용해 "1분 추가함, 남은 시간 X분 Y초"처럼 알린다

적용 범위는 프리셋/직접입력뿐 아니라 활동 단계·뽀모도로 등 **실행 중인 모든 큐 항목**에 동일하게 적용한다(엔진이 이미 단일 큐로 통합돼 있어 모드별 분기가 필요 없다).

### B2. 10초 카운트다운 효과음
`표시 & 소리` 섹션에 체크박스("종료 10초 전부터 매초 효과음") 추가, 기본값 **켬**.
기존 `chime()`(`index.html:903`)에 새 종류를 추가해 짧고 높은 톤을 만든다(기존 예고음·종료음과
음색이 겹치지 않게). 이미 존재하는 `danger` 임계값(10초 이하)을 그대로 재사용해 초 경계를
지날 때마다 한 번씩 울린다. 새 기준값을 만들지 않는다.

### B3. 글자색 사용자 지정
지금 `--text`(본문·라벨·제목 등 일반 글자색)는 테마별로 코드에 고정돼 있다
(라이트 `#0E1420`, 다크 `#EDF1F8`, `index.html:20`,`:36`). 이미 있는 "기본 타이머 색상"
(`--live` 계열, 큰 숫자·게이지 색)과는 별개로, 일반 글자색도 사용자가 고를 수 있게 한다.

`표시 & 소리`에 "기본 타이머 색상"과 나란히 "글자색" 항목을 같은 구조로 추가한다
(`<input type=color>` + `테마 기본값으로` 버튼 + 명암비 경고). 단, **라이트·다크 테마 값을
각각 따로 저장**한다 — 글자색은 배경과 짝을 이뤄야 읽히므로(밝은 배경엔 어두운 글자, 어두운
배경엔 밝은 글자), 값 하나를 공유하면 테마 전환 시 글자가 안 보이는 사고로 바로 이어진다
(기존 "기본 타이머 색상"이 라이트·다크 공유로 인해 겪는 것과 같은 문제를, 가독성이 훨씬
중요한 본문 글자에서는 피한다). 지금 보고 있는 테마의 값만 그 자리에서 바꾸는 UI이고,
명암비 경고는 본문 글자 기준(4.5:1)을 큰 숫자 기준(3:1)과 별도로 적용한다.
`--muted`(2차 텍스트)는 이번 범위에 포함하지 않고 기존 로직을 유지한다.
설정 저장 스키마·내보내기 JSON에 라이트/다크 각각의 키가 새로 추가된다.

## C. 컨트롤·설정 레이아웃 단순화

### C1. 보조 컨트롤 버튼 아이콘화
`시작`/`일시정지`만 텍스트 라벨이 있는 채워진(primary) 버튼으로 남기고, `초기화`·`다음`·
`전체화면`·B1의 `+10초`·`+1분`은 아이콘 버튼으로 바꾼다. 각 아이콘 버튼에는 기존 `title`
외에 명시적 `aria-label`을 단다(아이콘만 남으므로 스크린리더가 `title`에만 기대지 않게).

### C2. 설정 패널 → 접이식 사이드바 (오른쪽 유지)
현재 떠 있는 `⚙ 설정` 원형 버튼(`#panelBtn`)을 없애고, 화면 오른쪽 가장자리에 얇게 붙는
탭(손잡이)으로 바꾼다. 접혀 있을 때도 항상 보여 태블릿에서 호버 없이 눌리고, 펼치면 그
탭이 곧 닫는 손잡이가 된다. 위치는 오른쪽 유지 — "타이머를 먼저 보고 설정은 그다음"이라는
기존 읽기 순서를 그대로 따른다. `S`/`Esc` 단축키, `aria-expanded`/`aria-controls` 시맨틱,
A3의 포커스 관리는 트리거 요소만 바뀔 뿐 동일하게 적용된다.

## D. 설정 패널 정보 구조 정리

지금 설정 패널은 `빠른 시작`/`활동 단계`/`뽀모도로`/`표시 & 소리`/`단축키` 다섯 개가 아코디언
안에서 같은 무게로 나열돼 있다. 그런데 성격이 다른 것들이 섞여 있다 — 앞의 셋은 "타이머를
어떻게 시작할지"를 고르는 서로 대체 가능한 방법들이고, 뒤의 둘은 부가 설정·참고 자료다.
이 구분이 시각적으로 드러나지 않는 게 핵심 문제다.

### D1. 섹션 제목 축약
`활동 단계` → **`활동`** 으로 줄인다. `빠른 시작`·`뽀모도로`는 그대로 유지한다.
`빠른 시작` → `바로`도 검토했으나 기각했다 — 사용설명서 1장에 이미 "**바로** 시작하려면"
처럼 "즉시"라는 뜻의 흔한 부사로 "바로"가 쓰이고 있어서, 섹션 이름으로 쓰면 `기본`과
같은 종류의 용어 충돌(이번엔 기존 문서 문장과 정면으로 겹침)이 생긴다. `활동`은 이런
충돌이 없어 그대로 채택한다.

이 변경은 `index.html`의 `<summary>` 표시 텍스트뿐 아니라 **`사용설명서.md` 전체에서
`활동 단계`를 언급하는 모든 곳**(2, 3, 4, 5, 6장 등 다수)에도 함께 반영해야 용어가
어긋나지 않는다. 버튼 `id`(`secSteps` 등)는 내부 식별자이므로 바꾸지 않는다.

### D2. 세 섹션에 한 줄 부제 추가
`summary` 아래 작은 회색 부제를 달아, 처음 보는 사람도 세 방식의 차이를 즉시 알 수 있게 한다.
기존 문서 어휘(도입/활동/정리, 집중/휴식)를 그대로 가져와 구체적인 예시로 보여준다:
- 빠른 시작 — *숫자만 넣으면 바로 시작*
- 활동 — *도입 → 활동 → 정리, 순서대로 이어서*
- 뽀모도로 — *집중 25분·휴식 5분처럼 자동 반복*

### D3. 시각적 그룹화
`빠른 시작`·`활동`·`뽀모도로` 세 아코디언 항목을 감싸는 작은 그룹 소제목("타이머 시작")과
옅은 테두리/배경으로 한 묶음임을 보여준다. `표시 & 소리`는 그 아래 별도 묶음. `단축키`는
폰트 크기를 살짝 줄이고 위쪽 여백을 더 둬서 참고 자료라는 인상을 준다. 아코디언 각 항목이
독립적으로 펼침 상태를 기억하는 기존 동작(`state.settings.openSecs`)은 그대로 유지 — 그룹은
순전히 시각적 구분이고 상호작용 방식(여러 개 동시에 펼치기)은 바꾸지 않는다.

### D4. 헷갈리는 두 시각 버튼에 캡션 추가
`이 시각까지`(빠른 시작 안)와 `종료 시각에 맞춰 압축 시작`(활동 안)은 사용설명서에도 "왜
시각 입력칸이 두 개인지" 별도 설명이 필요했던 지점이다(`사용설명서.md` 4장). 각 버튼 바로
위에 한 줄 캡션을 추가해 그 자리에서 바로 구분되게 한다:
- 빠른 시작 쪽(`untilBtn` 위): *이 시간 하나만 잴 때*
- 활동 쪽(`fitBtn` 위): *짜둔 단계들을 이 시각에 맞춰 줄여서 시작*

### D5. 표시 & 소리 체크박스 문구 정리
`종료 후 초과 시간 표시 (+2:30)`처럼 이미 괄호 예시가 붙어 명확한 것은 그대로 두고,
나머지도 같은 패턴으로 맞춘다:
- `종료 알림음` → `종료 알림음 (단계 끝날 때 소리)`
- `종료 30초 전 예고음` → `종료 30초 전 예고음 (낮은 소리 두 번)`
- `현재 시각 · 종료 예정 시각 표시`는 라벨이 이미 내용을 그대로 서술하므로 유지

## 비범위 (Out of scope)

- 리본(수업 띠)의 스크린리더 텍스트 대안 — `stepName`의 "3/5" 표시로 이미 핵심 정보(진행
  단계/전체 단계 수)가 텍스트로 제공되므로, 리본 전용 요약 안내는 이번엔 추가하지 않는다.
- `+10초`/`+1분` 외 추가 증분(예: `+5분`)이나 시간 빼기 — 요청 범위 밖.
- 사이드바를 왼쪽으로 옮기는 안 — 검토 후 기각(오른쪽 유지로 결정).
- 3개 타이머 모드를 탭(하나만 열림)으로 바꾸는 안 — 검토 후 기각. 아코디언을 유지하고
  시각적 그룹화(D3)만 적용하기로 결정. 여러 개를 동시에 펼쳐 두고 훑어보는 기존 동작을 보존한다.
- `단축키`를 설정 그룹에서 완전히 빼서 별도 도움말(`?`)로 옮기는 안 — 검토 후 기각.
  그룹 안에 두되 톤을 낮춰 시각적으로만 분리하기로 결정(D3).
- 글자색(`--text`)을 라이트/다크 공유 단일 값으로 저장하는 안 — 사용자가 처음 요청했다가
  명암비 안전성 문제(테마 전환 시 글자가 안 보일 수 있음)를 설명한 뒤 철회. 최종적으로
  라이트/다크 개별 저장(B3)으로 결정.
- `--muted`(2차 텍스트) 커스터마이즈 — 요청 범위 밖, 기존 로직 유지.
